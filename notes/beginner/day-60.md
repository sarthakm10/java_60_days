## 🌿 Spring — Transactions & Hibernate

<!-- intro: d22_t1_s1 -->
Put **`@Transactional`** on a service method, and everything it does to the database happens in **one transaction**: if the method finishes, all changes are committed; if it throws a runtime exception, all are rolled back. A money transfer becomes safe with one annotation. It works through a **proxy** (Day 44): Spring wraps your bean, starts the transaction, calls your method, then commits or rolls back. That's why calling a `@Transactional` method from **another method in the same class** silently skips the transaction: the call never goes through the proxy. And by default, checked exceptions do **not** cause a rollback.

<!-- intro: d22_t1_s2 -->
If a transactional method calls another transactional method, should they share one transaction? **Propagation** decides. `REQUIRED` (the default) joins the existing one; `REQUIRES_NEW` pauses it and starts a separate one (use it for an audit log that must be saved even if the main work fails). Most of the time the default is right.

<!-- intro: d22_t1_s3 -->
Day 50's isolation levels, set per method: `@Transactional(isolation = Isolation.SERIALIZABLE)`. The default (the database's own, usually READ COMMITTED) is fine for most work. Read the table of anomalies once, so the names are familiar in interviews.

<!-- intro: d22_t1_s4 -->
Two people open the same product, both change the stock, both save: the second save silently overwrites the first (a *lost update*). **Optimistic locking** adds a `@Version` field: every save checks the version hasn't changed since you loaded the row, and fails with an exception if it has, so you can retry or tell the user. **Pessimistic locking** locks the row while you work on it (safer for heavy contention, slower).

<!-- intro: d22_t1_s5 -->
Inside a transaction, entities loaded by JPA are **managed**: change a field, and Hibernate saves it automatically when the transaction commits, without you calling `save`. That surprises everyone the first time. The section shows the states an entity goes through (new, managed, detached, removed).

<!-- intro: d22_t1_s7 -->
`ddl-auto=update` (Day 58) is fine for learning, but in a real project you need to know **exactly** what changes, in order, on every database. **Flyway** runs numbered SQL scripts (`V1__create_products.sql`, `V2__add_stock_column.sql`) once each, in order, and records which ones have run. Your schema is versioned in Git alongside your code. You'll use it in the project on Day 65.

### Step 7: Flyway migrations, transactions and optimistic locking

**Goal:** the database schema lives in versioned SQL files that run the same way on every machine (Flyway), services run inside transactions (so a two-step change can't half-happen), and two people editing the same task at the same moment can't silently overwrite each other (`@Version`).

**1. Add Flyway** to `pom.xml` (on Spring Boot 3.x use `org.flywaydb:flyway-core` instead of the starter):

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-flyway</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-database-postgresql</artifactId>
</dependency>
```

**2. The first migration.** Flyway runs every file in `src/main/resources/db/migration` once, in version order, and records it in a table called `flyway_schema_history`. It's the same tables Hibernate made, plus a `version` column, `CHECK` rules the database itself enforces, and an index:

```sql
-- src/main/resources/db/migration/V1__create_projects_and_tasks.sql
-- V1: the tables from Days 58-59, now created by Flyway instead of Hibernate

CREATE TABLE projects (
    id   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE tasks (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    project_id  BIGINT        NOT NULL REFERENCES projects (id),
    title       VARCHAR(200)  NOT NULL,
    description VARCHAR(2000),
    status      VARCHAR(20)   NOT NULL DEFAULT 'TODO' CHECK (status IN ('TODO', 'IN_PROGRESS', 'DONE')),
    priority    INTEGER       NOT NULL DEFAULT 3 CHECK (priority BETWEEN 1 AND 5),
    due_date    DATE,
    version     BIGINT        NOT NULL DEFAULT 0
);

-- The task list filters by project (and often by status): an index makes that fast as the table grows
CREATE INDEX idx_tasks_project_status ON tasks (project_id, status);
```

**3. Hibernate stops changing tables** and only checks that the entities match them (the app won't start if they don't):

```properties
# in application.properties
# Flyway creates the tables (src/main/resources/db/migration); Hibernate only checks they match the entities
spring.jpa.hibernate.ddl-auto=validate
```

**4. Start with an empty database.** Flyway refuses to run on a database that already has tables it didn't make. Your data so far is test data, so recreate the database (stop the app first):

```sql
DROP DATABASE taskmanager;
CREATE DATABASE taskmanager;
```

**5. Optimistic locking on tasks.** Add this field to `Task` (and `import jakarta.persistence.Version;`):

```java
// in Task.java
// Optimistic locking: every UPDATE checks "WHERE version = ?" and adds 1. If another request changed the row
// in the meantime, nothing matches and Spring throws ObjectOptimisticLockingFailureException (409, see the handler).
@Version
private Long version;
```

**6. Transactions in the services.** `@Transactional(readOnly = true)` on the class covers the reads; each method that writes gets its own `@Transactional`. Deleting a project shows why: two deletes that must both happen or neither.

```java
// src/main/java/com/example/taskmanager/project/ProjectService.java
package com.example.taskmanager.project;

import java.util.List;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import com.example.taskmanager.common.NotFoundException;
import com.example.taskmanager.task.TaskRepository;

// Every public method runs in a transaction. readOnly for reads (Hibernate skips change tracking);
// methods that write override it with a plain @Transactional.
@Service
@Transactional(readOnly = true)
public class ProjectService {

    private final ProjectRepository projectRepository;
    private final TaskRepository taskRepository;

    public ProjectService(ProjectRepository projectRepository, TaskRepository taskRepository) {
        this.projectRepository = projectRepository;
        this.taskRepository = taskRepository;
    }

    @Transactional
    public ProjectResponse create(CreateProjectRequest request) {
        Project saved = projectRepository.save(new Project(request.name()));   // INSERT; saved has its id
        return ProjectResponse.from(saved);
    }

    public List<ProjectResponse> list() {
        return projectRepository.findAllWithCounts();
    }

    public ProjectResponse get(Long id) {
        return projectRepository.findWithCountsById(id)
                .orElseThrow(() -> new NotFoundException("Project " + id + " not found"));
    }

    // Two deletes that must succeed or fail together: if deleting the project fails, its tasks come back (rollback)
    @Transactional
    public void delete(Long id) {
        Project project = find(id);
        taskRepository.deleteAllByProjectId(id);
        projectRepository.delete(project);
    }

    // The project itself, for TaskService; 404 if there's no such project
    public Project find(Long id) {
        return projectRepository.findById(id)
                .orElseThrow(() -> new NotFoundException("Project " + id + " not found"));
    }
}
```

```java
// src/main/java/com/example/taskmanager/task/TaskRepository.java
package com.example.taskmanager.task;

import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Modifying;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

public interface TaskRepository extends JpaRepository<Task, Long> {

    // "ProjectId" walks the relationship: ... WHERE project_id = ?, plus LIMIT/OFFSET and ORDER BY from the Pageable,
    // and a second COUNT query for the total
    Page<Task> findByProjectId(Long projectId, Pageable pageable);

    Page<Task> findByProjectIdAndStatus(Long projectId, TaskStatus status, Pageable pageable);

    // One DELETE statement for all of a project's tasks (a derived deleteBy... would load and delete them one by one).
    // @Modifying marks a query that changes data; it needs a transaction, which ProjectService.delete provides.
    @Modifying
    @Query("delete from Task t where t.project.id = :projectId")
    int deleteAllByProjectId(@Param("projectId") Long projectId);
}
```

`update` no longer calls `save()`: inside a transaction, Hibernate tracks the entities it loaded and writes the changes itself when the method returns (**dirty checking**).

```java
// src/main/java/com/example/taskmanager/task/TaskService.java
package com.example.taskmanager.task;

import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import com.example.taskmanager.common.NotFoundException;
import com.example.taskmanager.common.PageResponse;
import com.example.taskmanager.project.ProjectService;

@Service
@Transactional(readOnly = true)
public class TaskService {

    private final TaskRepository taskRepository;
    private final ProjectService projectService;

    public TaskService(TaskRepository taskRepository, ProjectService projectService) {
        this.taskRepository = taskRepository;
        this.projectService = projectService;
    }

    @Transactional
    public TaskResponse create(Long projectId, CreateTaskRequest request) {
        Task task = new Task();
        task.setProject(projectService.find(projectId));   // 404 if the project doesn't exist
        task.setTitle(request.title());
        task.setDescription(request.description());
        if (request.priority() != null) task.setPriority(request.priority());
        task.setDueDate(request.dueDate());
        return TaskResponse.from(taskRepository.save(task));
    }

    // One page of a project's tasks; status is optional (null = all)
    public PageResponse<TaskResponse> list(Long projectId, TaskStatus status, Pageable pageable) {
        projectService.find(projectId);
        Page<Task> page = status == null
                ? taskRepository.findByProjectId(projectId, pageable)
                : taskRepository.findByProjectIdAndStatus(projectId, status, pageable);
        return PageResponse.from(page.map(TaskResponse::from));
    }

    public TaskResponse get(Long id) {
        return TaskResponse.from(find(id));
    }

    // Only the fields the client sent change. No save() needed: the task was loaded in this transaction, so
    // Hibernate notices the changes and writes one UPDATE when the method returns (dirty checking).
    @Transactional
    public TaskResponse update(Long id, UpdateTaskRequest request) {
        Task task = find(id);
        if (request.title() != null) task.setTitle(request.title());
        if (request.description() != null) task.setDescription(request.description());
        if (request.status() != null) task.setStatus(request.status());
        if (request.priority() != null) task.setPriority(request.priority());
        if (request.dueDate() != null) task.setDueDate(request.dueDate());
        return TaskResponse.from(task);
    }

    @Transactional
    public void delete(Long id) {
        taskRepository.delete(find(id));
    }

    private Task find(Long id) {
        return taskRepository.findById(id)
                .orElseThrow(() -> new NotFoundException("Task " + id + " not found"));
    }
}
```

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.InOrder;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import com.example.taskmanager.common.NotFoundException;
import com.example.taskmanager.task.TaskRepository;

@ExtendWith(MockitoExtension.class)
class ProjectServiceTest {

    @Mock
    ProjectRepository projectRepository;

    @Mock
    TaskRepository taskRepository;

    ProjectService projectService;

    @BeforeEach
    void setUp() {
        projectService = new ProjectService(projectRepository, taskRepository);
    }

    @Test
    void deleteRemovesTheTasksFirstThenTheProject() {
        Project project = new Project("Website");
        when(projectRepository.findById(1L)).thenReturn(Optional.of(project));

        projectService.delete(1L);

        // tasks point at the project (foreign key), so they must go first
        InOrder order = inOrder(taskRepository, projectRepository);
        order.verify(taskRepository).deleteAllByProjectId(1L);
        order.verify(projectRepository).delete(project);
    }

    @Test
    void deletingAMissingProjectDeletesNothing() {
        when(projectRepository.findById(9L)).thenReturn(Optional.empty());

        assertThatThrownBy(() -> projectService.delete(9L)).isInstanceOf(NotFoundException.class);
        verify(taskRepository, never()).deleteAllByProjectId(any());
    }
}
```

**8. Try it.** Start the app: the log says Flyway applied version 1. In psql, `SELECT version, description, success FROM flyway_schema_history;` shows it, and `\d tasks` shows the constraints. Try `UPDATE tasks SET priority = 9;` in psql: the database refuses it, even though no Java code is involved.

**See a rollback.** In `ProjectService.delete`, add `if (true) throw new IllegalStateException("boom");` between the two deletes, restart, and delete a project that has tasks. The request fails, and the tasks are **still there**: the first delete was rolled back. Remove the line.

## 📝 Day 60 Recap

1. What does @Transactional do? → **runs the method in one transaction: commit on success, rollback on a runtime exception**
2. How does @Transactional work underneath? → **through a proxy that wraps the bean**
3. Why does calling a @Transactional method from the same class skip the transaction? → **the call doesn't go through the proxy**
4. Do checked exceptions roll back by default? → **no, only runtime exceptions and errors**
5. Default propagation? → **REQUIRED: join the existing transaction or start one**
6. When use REQUIRES_NEW? → **for work that must commit separately, e.g. an audit log**
7. What does @Version enable? → **optimistic locking: a save fails if someone else changed the row**
8. What is a managed entity? → **one loaded inside a transaction, whose changes are saved automatically on commit**
9. What does Flyway do? → **runs numbered SQL migration scripts once each, in order, and tracks them**
10. Flyway file name for the first migration? → **V1__description.sql**
